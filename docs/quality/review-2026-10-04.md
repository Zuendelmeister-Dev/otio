# Code and documentation review — 4 October 2026

Reviewed local commit `ae262b2905ac9549dfc990c2ab75fdd507904018` on `feature/ui-usability-release`. This review describes that checkout; it does not establish the state of a newer remote branch. Application, deployment and documentation sources were inspected in parallel and important findings were cross-checked. No application or deployment files were changed.

The subsequent implementation and its verification are documented separately in [Implementation and verification — 4 October 2026](implementation-2026-10-04.md). Findings and coverage below describe the original reviewed commit.

## Assessment

OT.io has a useful modular foundation: Sense separates protocol readers/subscribers from its publisher, shared MQTT code centralizes transport behavior, protocol fixtures exercise native wire formats, and deployment examples distinguish application traffic from UI access. Screenshots and the newer Mermaid diagrams substantially improve onboarding. The documentation states the limits of native drivers, HA and QoS 0 clearly.

The main weakness is consistency between layers. Transport-library state is interpreted too optimistically, asynchronous UI state can become associated with the wrong instance, deployment packaging has fallen behind Dockerfiles, and older instructions coexist with newer APIs. Passing unit/static checks currently misses these cases.

## Highest-priority findings

### 1. P1 — A delayed configuration response can target the wrong collector

**Location:** [Lense detail loader](../../apps/lense/static/index.html#L702), particularly `currentLenseConfigItem` at line 707, the awaited response at line 715 and validation/apply at lines 751/786.

Opening configuration A and then B starts independent loaders. If B completes before A, A's late response replaces the title/editor, while `currentLenseConfigItem` still points to B. A controlled response-order probe produced `applyTarget=B`, `title=Collector A configuration`, `editor=CONFIG_A`. Validation subsequently sends that displayed draft to B. If both configurations are valid, applying it can overwrite the wrong collector.

**Recommendation:** Give each navigation/load a generation token or AbortController, discard late results, and bind the validated draft, component ID and proposal ID together. Add a behavioral test with deliberately reversed response order. Apply the same response-ownership rule to reset and history loading.

### 2. P1 — The Raspberry Pi source archive cannot build Sense or Lense

**Locations:** [Ansible archive command](../../deploy/ansible/roles/deploy_stack/tasks/main.yml#L50), [Sense Dockerfile](../../apps/sense/Dockerfile#L18), [Lense Dockerfile](../../apps/lense/Dockerfile#L18).

The deployment archive contains `apps shared db deploy/mosquitto go.work`, while both Dockerfiles copy `examples/03-protocol-lab`. The Pi Compose stacks build from the extracted `./repo`, where that directory is absent. A fresh deployment fails when Docker resolves the COPY source. This follows from the package contents and Dockerfiles; no live Pi rollout was available.

**Recommendation:** Include the required directory and test image builds from the actual extracted Ansible archive in CI. Builds directly from the full Git checkout do not cover this failure.

## Other operational findings

### 3. P2 — MQTT reconnects can inflate successful-publication counters

**Locations:** [Connectivity predicate](../../shared/mqttx/client.go#L71), [Sense publish accounting](../../apps/sense/internal/app/sense_transport.go#L74), [Dispense forwarding](../../apps/dispense/dispense_transport.go#L112).

Paho's `IsConnected()` remains true during reconnect. In that state its QoS 0 publish can return success without sending or storing the payload. The local probe confirmed a closed connection, a true OT.io connectivity predicate and a nil publish error. Sense/Dispense then increment counters and update timestamps/traffic views describing successful publications.

**Recommendation:** Distinguish an open transport connection from the broader client lifecycle state, and make counter labels reflect what is actually confirmed. An open-connection check reduces the misleading case; QoS 0 still provides no broker delivery acknowledgement and races can still occur. Guaranteed delivery would require a separate design.

### 4. P2 — Dispense is reported healthy when its brokers are disconnected

**Locations:** [Component probe](../../apps/lense/component_monitor.go#L155), [Dispense status response](../../apps/dispense/api.go#L18).

For non-Sense components, any successful HTTP response becomes healthy. Dispense's API remains reachable while input/output brokers are disconnected and already reports both flags. A probe returning both flags false still produced healthy status.

**Recommendation:** Keep API reachability separate from operational health, parse the Dispense status and require the appropriate broker connections. Treat malformed Sense/Dispense status responses as unknown/degraded rather than healthy.

### 5. P2 — A long-running subscription retains every received metric name

**Location:** [Sense subscription collector](../../apps/sense/internal/app/collector.go#L257).

Each subscription update appends a name to `received`. A continuous OPC UA stream does not return until it terminates, so the slice grows for the lifetime of the connection. On termination all names are joined into a potentially enormous health message. Per-metric chart bounds do not bound this slice.

**Recommendation:** Retain only whether a value arrived, or a set bounded by the configured metric names. The callback already updates source health for each value.

### 6. P2 — Starting MQTT also starts AMQP publication

**Location:** [Protocol Lab publisher](../../apps/protocol-lab/brokers.go#L124).

The MQTT branch checks the selected protocol, but the AMQP branch only checks whether `LAB_AMQP_URL` exists. With both URLs configured, starting only MQTT also attempts AMQP publication. Starting both creates duplicate AMQP publishers, and stopping AMQP leaves the MQTT worker's AMQP activity running. The lifecycle probe reproduced this. Existing round-trip tests clear the other broker variable and therefore miss it.

**Recommendation:** Gate both branches by the requested protocol, and test combined start/stop states with both endpoint variables configured.

### 7. P2 — An apply can report failure after committing the configuration

**Locations:** [Three-second Lense proxy timeout](../../apps/lense/api.go#L56), [Sense apply sequence](../../apps/sense/internal/app/api.go#L115), [Transport connection wait](../../apps/sense/internal/app/sense_transport.go#L59).

Sense writes the configuration before synchronously restarting transport. Its broker connection can wait five seconds, while Lense waits only three seconds for the whole apply response. With an unavailable broker, Lense can report HTTP 502 even though the configuration was saved and the restart proceeds.

**Recommendation:** Separate configuration acceptance from connection recovery, return an explicit applying/reconnecting state, and provide an operation result users can retrieve. At minimum align the timeout budgets and document commit semantics. This finding is based on the execution path and timeout values, without a fresh full-stack apply exercise.

### 8. P2 — Subscription metrics sharing a node overwrite each other

**Location:** [OPC UA HTTP subscription mapping](../../apps/sense/internal/protocols/opcua_http.go#L60).

Validation permits different metric names referring to the same node, for example raw and scaled views. `metricsByNode` stores only one metric per node. The alias probe emitted only the final alias.

**Recommendation:** Map each node to all configured metrics or explicitly reject duplicate node mappings. Test behavior consistently across polling and subscription modes.

### 9. P2 — Hierarchical MQTT prefixes break heartbeat and namespace handling

**Locations:** [Lense topic classification](../../apps/lense/lense_transport.go#L70), [UNS filtering](../../apps/lense/api.go#L543).

The shared topic builders support a prefix such as `factory/line`, but Lense uses `parts[1]` as the agent or `_sense` identifier. That segment is `line` for a multi-segment prefix. Heartbeats are misclassified and observed metric topics are filtered out of the namespace view.

**Recommendation:** Remove/parse the configured prefix before extracting the agent and topic kind, using a shared topic parser with multi-segment prefix tests.

### 10. P2 — CSV export corrupts valid string values

**Location:** [Lense export row construction](../../apps/lense/api.go#L604).

The server export concatenates fields with commas. Metric text or units containing commas, quotes or newlines produce malformed CSV. The separate browser database exporter already quotes fields, so the two export paths behave differently. The server also ignores query/scan errors and can return an apparently successful empty/partial export.

**Recommendation:** Use `encoding/csv.Writer`, check database/scan/write errors and cover multiline and quoted values. This was confirmed from the exporter code rather than a live database export.

### 11. P2 — Normal Ansible deployment discards runtime configuration

**Locations:** [Runtime-file deletion](../../deploy/ansible/roles/deploy_stack/tasks/main.yml#L38), [Environment template](../../deploy/ansible/templates/env.j2), [Example 02 token instruction](../../examples/02-raspberry-pi-arm-distributed/README.md#L100).

Normal deploy deletes `.env` and the complete `config` directory, including user-edited Sense configuration/history, before rendering replacements. The README instructs users to set a configuration-write token in the rendered `.env` before deployment, but the next deploy deletes it and the template leaves that token commented out. A separate reset workflow already exists.

**Recommendation:** Preserve runtime data during ordinary redeploy, seed absent files, provide explicit reset behavior, and inject the token through an Ansible variable rather than a file that deploy replaces.

## Documentation inconsistencies

1. **P2 — Nonexistent troubleshooting commands.** [Troubleshooting](../troubleshooting.md#L9) refers to `scripts/start-demo.*`; the actual helpers are `start-local-docker-compose-demo.*`. Its base-image commands also use old Go/Alpine versions. The claimed preflight pull behavior is not implemented by the current switch handling. Update commands and test executable paths inside code blocks.

2. **P2 — Manual MQTT commands omit listener configuration.** [Deployment](../deployment.md#L67) and [configuration rollout](../configuration-rollout.md#L440) run Mosquitto without the configuration mounted by Compose. Mosquitto 2 defaults to container-local loopback listeners, so other containers cannot use those brokers. Mount the existing demo configuration. This behavior is documented by [Eclipse Mosquitto](https://mosquitto.org/documentation/migrating-to-2-0/); no Docker instance was started for this check.

3. **P2 — Copyable source configurations fail validation.** [Sense extension example](../sense.md#L262) places `pollIntervalMs` inside a source, where the strict decoder does not accept it. Its string metric and the [Presense source example](../presense.md#L234) omit the mandatory nonzero scale. Move the interval to the top level and include `scale: 1` where no conversion is intended. Registration of a custom protocol alone does not resolve these schema errors.

4. **P2 — Subscriber extension instructions exceed validator support.** [Sense subscriber guide](../sense.md#L408) describes registered custom subscribers, while [configuration validation](../../apps/sense/internal/app/config.go#L92) allows subscription only for the literal type `opcua`. Validate registered capabilities rather than protocol names. This affects the documented extension path; it is not a claim that additional built-in subscription implementations already exist.

5. **P2 — Example 04 directs users to unavailable UI choices.** [Device-gateway guide](../../examples/04-device-gateways/README.md#L36) directs readers to select BACnet/KNX in a UI whose [selector](../../apps/protocol-lab/static/lab.js#L46) intentionally filters to TCP. Provide a separate API/Sense JSON workflow for these UDP adapters, including network prerequisites.

6. **P3 — Conflicting extension and feature descriptions.** [Earlier Sense extension instructions](../sense.md#L196) describe different file locations and a `SourceReader` interface that does not match the later `internal/protocols` guide. [Architecture](../architecture.md#L212) and [rollout documentation](../configuration-rollout.md#L126) still describe native encrypted OPC UA/certificates as future work, while [certificate profiles](../certificates.md) are implemented. [Configuration](../configuration.md#L77) also describes Presense as environment-only despite its writable/persistent settings API. Consolidate the canonical instructions and distinguish the legacy HTTP demo from native OPC UA.

The current example diagrams for local Compose, Protocol Lab, Kustomize and Helm matched the inspected ports and communication paths. Older deployment diagrams should be marked as legacy or updated to include the current Lab/broker components.

## Code quality and extension priorities

1. **Correct instance ownership and deployment packaging first.** Fix findings 1 and 2 with regression tests for reversed response order and the extracted ARM archive.
2. **Make status and event accounting trustworthy.** Fix reconnect predicates, component health, subscription bounds and simulator isolation before adding new transport families. Normalize source quality: [metricPayload](../../apps/sense/internal/app/collector.go#L69) currently labels all readings `good` even when adapter raw data carries bad/uncertain quality.
3. **Use one protocol capability description.** Drive registry support, polling/subscription validation, UI choices, address presets and the support matrix from the same capabilities. Provide a compilable minimal custom reader/subscriber example, preserving the built-in registrations.
4. **Test workflows rather than source markers.** Fifteen of Lense's 28 Go test files read `static/index.html`; many assert string fragments. Add focused browser tests for delayed navigation, validation/apply/reset, keyboard flow highlighting and broker recovery. The graph currently replaces its entire DOM during the five-second summary refresh ([render](../../apps/lense/static/index.html#L1126)), so keyboard focus needs explicit preservation. Extract navigation/configuration state from the 1,658-line HTML page and make request ownership testable.
5. **Validate executable documentation.** Check configuration examples with the real validators, command paths against repository files, and packaged deployment contexts in CI. Reduce duplication across configuration/deployment/module guides. Keep dated records, but add links to the CI run for the tested commit rather than presenting historical local checks as current evidence.
6. **Extend resilience testing to a hung child process.** The HA supervisor's [liveness endpoint](../../apps/ha-agent/main.go#L141) always succeeds. A running but unresponsive child can lose readiness while its supervisor continues renewing the Lease. Add failure thresholds and a defined restart/takeover path, then exercise application hangs and storage/broker recovery, beyond Pod deletion tests.
7. **Add practical data-management features after correctness fixes.** Historian retention/downsampling, backup/restore exercises, bounded agent/topic cardinality, and alerts for stale data would improve long-running deployments. Preserve quality/units and distinguish stale, unavailable and valid readings. A durable forwarding buffer with retry/backoff and deduplication could be a separate mode when best-effort QoS 0 is insufficient; it should have explicit delivery semantics.
8. **Expand outbound integrations through interfaces.** Sense already has an `EventPublisher` seam. A corresponding target-publisher interface for Dispense would enable HTTP or other broker targets without duplicating filtering, accounting and buffering. Keep Protocol Lab publishers connected between samples instead of repeatedly reconnecting once per second, and expose connection/retry state separately from message rates.

Suggested first batch: findings 1–2, then 3–6, followed by documentation consolidation and validated extension examples. Reassess new feature scope after the workflow/failure tests cover these paths.
