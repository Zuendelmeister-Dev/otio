# Maintenance review — September 2026

Reviewed on 2026-09-13. OT.io remains suitable for local beta evaluation; this review does not establish production readiness.

## Changes

- MQTT connect and publish now return a timeout error when the token has not completed. Previously a pending token could report success, including falsely increasing Dispense's forwarded counter. A timeout does not cancel the underlying operation; delivery can still occur later, and the dropped counter represents failed or unconfirmed forwarding attempts.
- MQTT broker URLs and the Modbus reader now support IPv6 host literals.
- Modbus reads validate transaction ID, protocol ID, unit ID, response length, function and byte count. Malformed and unrelated responses are rejected before their value is accepted.
- Dispense validates its buffer limit, preventing negative slice bounds. Invalid JSON configuration no longer partially overwrites defaults, and is logged. Invalid incoming JSON increments the dropped counter; deliberately filtered messages do not.
- Dispense forwards string, boolean and null values unchanged. Only numeric values enter its chart buffer, matching Sense's numeric chart behavior.
- PowerShell test and coverage runners check native exit codes, and the Makefile stops at the first failing Go module. Test scripts resolve paths from their own location. Coverage profiles use ASCII to work with Windows PowerShell 5.1 as well as PowerShell 7.
- Dependencies were updated to Paho MQTT 1.5.1 and `golang.org/x/net` 0.59.0, with module checksums checked in. Modules require Go 1.26; the workspace selects the patched Go 1.26.8 toolchain. Docker builds use Go 1.26.8 and Alpine 3.24.
- A GitHub Actions workflow was added for Windows/Linux tests, coverage artifacts, Linux vet/race checks, vulnerability scanning and demo container builds. It has not yet run on GitHub.
- README setup requirements and development commands were clarified, duplicate deployment notes consolidated, and the HTTP-based OPC UA demo explicitly distinguished from native OPC UA.

## Verification

- All seven Go modules and both JavaScript suites passed using the Windows wrapper.
- Coverage generation produced per-module summaries and `coverage/coverage.html` successfully using Windows PowerShell.
- `go vet` passed across the workspace.
- `govulncheck` 1.1.4 reported **No vulnerabilities found** on Windows/amd64 with Go 1.26.8 and the updated dependencies. The earlier scan found ten reachable advisories across the old dependencies and Go 1.26.3. This is a point-in-time Go scan, not a container scan.
- All Compose files passed configuration validation. Distributed node templates were checked with `--no-env-resolution` because their deployment-generated `.env` files are not present locally.
- Docker builds and live end-to-end checks were unavailable: no Docker daemon was running. Local race detection was unavailable because CGO/a C compiler was not configured. Both checks are included in the new Linux CI job but are not claimed as passed.

## Remaining priorities

1. Add real MQTT reconnect/disconnect and Postgres integration tests, including persistence failures and recovery. Current transport tests use fake clients; protocol tests use a local TCP server.
2. Increase Lense runtime/API coverage and replace selected HTML substring assertions with browser interaction tests. Source-string assertions alone do not verify rendered behavior.
3. Propagate request cancellation through the Modbus reader, and bound and check request/response body reads in Lense's remote configuration proxy. Its current `io.ReadAll` errors are ignored.
4. Bound agent/topic cardinality in long-running in-memory telemetry stores; per-series history limits do not bound the number of series.
5. Exercise configuration apply/rollback, broker recovery and ARM rollout on the actual demo stack. Review authentication, TLS, secrets and backup requirements before expanding beyond a trusted lab.

## Protocol Lab follow-up

The subsequent protocol expansion adds an eighth Go module and native Modbus TCP, RTU-over-TCP and OPC UA round-trip tests. The full Windows test wrapper, JavaScript suites, `go vet` and coverage generation pass with Go 1.27.1. Current statement coverage is **32.1%** overall and **51.5%** for Protocol Lab; adding the new module changes the denominator. A follow-up scan using govulncheck 1.8.0 found no vulnerabilities.

The browser check verified simulator edits and a native OPC UA read returning the edited value (31.2). The example configuration and Lense topology are checked together by regression tests. Example 03 passes Compose configuration validation. Actual broker tests skip locally when broker endpoints are absent; Docker builds, race detection and physical-device interoperability remain unverified locally.
